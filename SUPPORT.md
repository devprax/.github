# Getting help with DevPrax projects

Start with the affected project's README, documentation, troubleshooting guidance, and existing issues. Project-specific support instructions take precedence over this organization-wide guide.

## Questions and troubleshooting

Use the affected repository's **Discussions** tab when it is enabled. If Discussions is unavailable and the project lists no other support channel, open an issue with a clear title such as `Question: configuring an integration`. Use a blank issue for questions rather than the bug report form.

Include what you are trying to achieve, the project version, your environment, what you have tried, and relevant sanitized output. Never include passwords, API keys, access tokens, or private user data.

## Bugs and feature requests

- **Bug:** Open an issue in the affected repository using the bug report form. Include reproduction steps, expected and actual behavior, and version and environment details.
- **Feature or improvement:** Use the feature request form in the relevant repository. Explain the problem or use case, the proposed outcome, and alternatives you considered.
- **Organization profile or shared guidelines:** Open an issue in [devprax/.github](https://github.com/devprax/.github/issues).

Search existing issues first. Add useful details to an existing report when it matches your problem. Keep reports focused on one topic.

## Sensitive reports

- For suspected vulnerabilities, follow the [Security Policy](https://github.com/devprax/.github/blob/main/SECURITY.md).
- For community conduct concerns, follow the [Code of Conduct](https://github.com/devprax/.github/blob/main/CODE_OF_CONDUCT.md), which explains the current reporting limitations.

Do not post sensitive reports publicly.

## Response expectations

DevPrax is an independent open-source initiative. Help and review depend on maintainer and community availability; there is no guaranteed response time or dedicated support service. Contributions that improve documentation and troubleshooting guidance are welcome—see [Contributing](https://github.com/devprax/.github/blob/main/CONTRIBUTING.md).
